Airgent is a local-first personal agent base system. The pi agent kernel does the thinking — model routing, file & shell tools, compaction — while Airgent exposes it through a CLI, a TUI, an HTTP API, and a WebUI, with transcripts and long-term memory in a local SQLite store.

§ 01

Capabilities

Modern-agent machinery, one flag away. Everything below is opt-in — flip an environment variable when you need it, and off again when you don't.

◍

Sandbox

Run the kernel inside a macOS Seatbelt profile, a Docker container, or an unprivileged Linux Landlock ruleset. Tiered: read-only, workspace-write, or full; network denied by default.

AIRGENT_SANDBOX=landlock · _MODE=read-only
✦

Skill registry

Per-skill enable/disable on top of pi's native .agents/skills discovery, with a default-deny mode and extra skill dirs.

AIRGENT_SKILLS_REGISTRY=1
⇄

MCP servers

Bridge external MCP servers (Claude-Desktop-compatible config) into the kernel. Each server's tools appear as mcp__server__tool.

AIRGENT_MCP=1
⑂

Sub-agents

Delegate self-contained subtasks to fresh headless agents and collect their final answer. Depth-capped so trees terminate.

AIRGENT_SUBAGENTS=1
⛌

Guardrails

Policy-driven tool-call filtering: denied commands, denied paths, denied tools, bash timeout caps — enforced inside the kernel.

AIRGENT_GUARDRAILS=1
🛡

Permissions

Tiered tool permissions with interactive approval: read-only or workspace-write, dangerous commands ask you first — in the TUI, the WebUI, or auto-denied headless.

AIRGENT_PERMISSION_MODE=workspace-write
↩

Rewind

Session checkpoints on the pi kernel's native fork: rewind any conversation to an earlier message from the CLI, TUI, or API — always on.

airgent sessions rewind
⟳

Lifecycle hooks

Turn-level before_run / after_run hooks, plus tool-level before_tool / after_tool hooks (exit 2 blocks the tool) — Claude-Code style, one hooks.json.

AIRGENT_HOOKS=1
☰

Plan mode

Read-only runs that end in a numbered implementation proposal. Write tools blocked for the run; you approve before anything executes.

airgent chat --plan · /plan
$

Cost tracking

Per-run token and cost usage recorded from the kernel, cumulative spend on demand, and an optional hard budget cap that refuses further runs.

AIRGENT_MAX_BUDGET_USD=10
◉

Memory system

Kinds & importance, time decay on access, near-duplicate merging, Letta-style core blocks, automatic fact extraction — and hybrid semantic + keyword retrieval (sqlite-vec, RRF fusion).

AIRGENT_MEMORY_EMBEDDINGS=1
⤓

Skills install

Install skill packages from any git URL with a shallow clone; single skills and collections both load through the kernel's --skill flag.

airgent skills install <url>
⇈

MCP server

Airgent itself speaks MCP: other agents (Claude Desktop, other CLIs) consume its memory, sessions, and kernel as tools over stdio.

airgent mcp-serve
⏪

Stream rules

omp-style time-traveling rules: regex patterns abort the stream mid-token, inject the instruction, and replay the task.

AIRGENT_STREAM_RULES=1
⌗

Tracing

Observability for every turn: run starts, ends, and errors persisted as trace events you can query.

AIRGENT_TRACING=1
◐

Cron

Schedule prompts on cron expressions, intervals, or one-shots. Jobs run through the same kernel and land in the transcript.

airgent cron create

Simple by default

With no configuration, Airgent is the thinnest useful wrapper around pi: native skill discovery, built-in file & shell tools, and the bundled memory tools. No sandbox, no registry, no policy files.

Power when asked

Each capability is an independent flag like AIRGENT_MCP=1. Enable exactly what you need, inspect the state with airgent status or GET /api/v1/features.
